Module 1Meet Claude Code

Lesson 1 of 6 · 10 min read

What Claude Code is

Claude Code is Anthropic’s agentic coding tool. Instead of chatting about code in a browser tab, it works inside your project: it can read your files, search the codebase, edit code, run commands and tests, and explain what it did.

Where it runs

Claude Code is available in the terminal (as a command-line tool), as a desktop app, on the web, and inside IDEs such as VS Code and JetBrains. The surface changes; the idea is the same — an agent that operates on a real project with your permission.

How it differs from a chatbot

  • It has context. It reads the actual code instead of the snippet you remembered to paste.
  • It takes actions. It edits files and runs commands, then checks the result.
  • It asks permission. Actions go through a permission system you control, from “ask me every time” to pre-approved commands.

In the language of the Foundations course, Claude Code is an agent: a model with tools (file editing, shell, search) running in a loop.

Key takeaways
  • Claude Code is an agent that works inside your project.
  • Runs in terminal, desktop, web and IDEs.
  • It reads, edits, runs and verifies — with your permission.
Lesson 2 of 6 · 10 min read

How a session actually works

A typical Claude Code session looks like a conversation with a very fast colleague who can touch the keyboard:

  1. You describe the goal in plain language: “Add a full-screen button to the launch video.”
  2. It explores: finds the relevant files, reads how the video player works today.
  3. It plans and edits: makes the change across the files that need it.
  4. It verifies: runs the app or tests, checks for errors, looks at the result.
  5. It reports: what changed, what it checked, and anything it couldn’t verify.

You stay in the loop the whole time — approving commands, redirecting it (“smaller photo, please”), and deciding what gets committed and shipped.

A real example

This portfolio — the redesign, the launch film section, the articles and these courses — was built in conversation with Claude Code. The pattern was always the same: describe the outcome, let the agent do the legwork, review the result, and approve anything that goes live.

Key takeaways
  • Goal → explore → edit → verify → report.
  • You approve actions and steer direction.
  • Shipping decisions stay with the human.

Module 2How it changes your role

Lesson 3 of 6 · 12 min read

For product managers

Claude Code is not only for engineers. For product managers it collapses the distance between an idea and something people can click on.

  • Prototypes in hours, not sprints. A clickable prototype makes a discussion concrete faster than any slide.
  • Answers from the code itself. “How does our discount logic actually work?” — ask the agent to read the codebase and explain it, with file references.
  • Data without waiting. Draft and run the query or script that answers a product question, instead of filing a request.
  • Better specs. Ground PRDs and acceptance criteria in how the system really behaves today.
  • Internal tools. Small dashboards and automations that would never make the engineering roadmap.

What doesn’t change

Judgment. Deciding what to build, for whom, and why — and saying no to the rest — is still the job. The agent makes building cheaper, which makes choosing well more important, not less.

Key takeaways
  • PMs can prototype, investigate and analyse directly.
  • Ground specs in how the system actually works.
  • Cheaper building makes prioritisation more important.
Lesson 4 of 6 · 10 min read

For engineers and designers

Engineers

  • Delegate the well-specified work — migrations, test coverage, repetitive refactors, boilerplate — and spend more time on architecture and review.
  • Onboard to unfamiliar code faster by asking the agent to trace a flow end to end.
  • Shift from writing every line to specifying, reviewing and verifying. Code review becomes a core skill, not a chore.

Designers

  • Turn a design into working front-end code and iterate on the real thing, in the browser, at real screen sizes.
  • Explore variations quickly — layouts, states, dark mode — and judge them live rather than in static mocks.

For everyone: the new core skill

The common thread is clear specification. The better you can describe the outcome, the constraints and how to check the result, the better the agent performs. Writing a good brief is now a technical skill.

Key takeaways
  • Engineers shift towards specifying, reviewing and verifying.
  • Designers iterate on real, working interfaces.
  • Clear specification is the core skill for everyone.

Module 3Working well and safely

Lesson 5 of 6 · 12 min read

Set your project up for success

Project instructions (CLAUDE.md)

A CLAUDE.md file in your project gives Claude Code standing instructions every session: how to run the app, coding conventions, what not to touch, and team rules. For example, the AI PM Agent’s instructions say: draft Jira changes but never create them without approval, check for duplicate stories first, and cite a source for every claim.

Habits that make sessions go well

  • State the outcome and how to check it. “Users can watch the film full screen; verify in the browser.”
  • Plan before big changes. Ask for a plan, review it, then let it build.
  • Keep changes small and reviewable. One feature per change makes review and rollback easy.
  • Give feedback like you would to a colleague. Screenshots and specific corrections work well.

Extending it

Teams can add skills (packaged instructions for recurring tasks), hooks (automatic checks that run at set moments) and MCP servers (connections to tools like Jira, Confluence or databases). Start without them; add them when a need repeats.

Key takeaways
  • CLAUDE.md holds standing project rules.
  • State outcome + how to verify; plan before big changes.
  • Add skills, hooks and MCP when needs repeat.
Lesson 6 of 6 · 10 min read

Guardrails: permissions, review and approval

An agent that can edit files and run commands needs guardrails. Claude Code gives you several layers:

  • Permissions. Decide which actions need approval each time and which are pre-approved. Start strict; loosen as trust grows.
  • Review the diff. Read what changed before you commit. Treat agent code like any other contribution.
  • Version control. Work on a branch and commit often — every change becomes easy to undo.
  • Human approval for outward-facing actions. Pushing to production, sending messages, deleting data or changing shared systems should always be a deliberate human decision.
  • Protect secrets. Keep API keys and credentials out of prompts and out of the repository.
The agent can move fast because you can review and reverse. Keep both of those true and you can safely delegate a lot.
Key takeaways
  • Use permissions, diffs and version control as layers of safety.
  • Outward-facing and irreversible actions need human approval.
  • Never put secrets in prompts or repos.
